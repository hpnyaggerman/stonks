# v5 return-prediction backbone

v5 predicts, per ticker per day, the **full distribution** of the volatility-normalized forward log-return at four horizons (1d / 1w / 1m / 6m), using a **Mamba (selective state-space) ensemble in PyTorch** with a 60-bin histogram head. Everything a decision rule needs is a functional of that histogram:

- **three-class probabilities** `{down, neutral, up}` — exact partial sums of bin mass on either side of per-horizon thresholds that land on bin edges;
- **aleatoric uncertainty** (market noise) — the histogram width / quantiles;
- **epistemic uncertainty** (model disagreement) — the spread across ensemble members;
- **return quantiles** `q10 / q50 / q90` in raw-return units.

A single trained head therefore serves any threshold, ranking, or interval rule without retraining.

## Feature contract — `features_v5.py`

`features_v5.py` is the single builder used by **both** the trainer and the live scorer, so the two cannot drift. It reads OHLCV, recomputes the full price-derived indicator suite in-builder, and emits **40 stationary channels** in a frozen order: log-returns (5), MA/EMA ratio gaps (5), Bollinger position/width (2), MACD relatives (2), oscillators (`rsi`, `zscore`), volatility (7, incl. the EWMA `log_sigma_hat` and the 60-day volume z-score `vol_z`), `fg` + `fg_corr`, derived momentum/gap/skew (6), eight sin/cos calendar phases (week, month, year, quarter), and the `is_pad` validity flag. No channel is monotone in time or proxies the era a row came from.

- **Window**: 252 rows ending at the prediction date inclusive (no "+1" convention).
- **Short histories**: left-padded with zeros (the post-scaling median) and an `is_pad=1` marker. The hard floor is **126 real rows** — computed as `max(warm_up + lag)` over the channels (the 126-day `fg_corr` dominates), never hand-set; below it a ticker is `insufficient_window`.
- **Normalization**: per-channel pooled robust-z (median, `IQR/1.349`) fit on training rows only, clipped to `[-10, 10]`, with a degenerate-scale fallback chain (`MAD → std over nonzero → 1`). Bounded/affine channels (calendar, `rsi`, `fg`, `fg_corr`, `zscore`, `is_pad`) pass through. Output is round-tripped through fp16, so trainer and scorer see bit-identical inputs.
- **Self-verifying spec**: the ordered channel list is hashed; the metadata and normalization files carry the hash and assert it at load. New channels are inert until appended to the spec.

## Labels

For horizon `h` with day count `d_h`:

```
y_{t,h}  = ln(C_{t+d_h} / C_t)                         # forward log-return
sigma2_t = 0.94 * sigma2_{t-1} + 0.06 * r_t^2          # RiskMetrics EWMA daily variance
z_{t,h}  = y_{t,h} / (sigma_hat_t * sqrt(d_h))         # the regression target
```

Vol-normalization is causal and replaces any fitted per-ticker label statistic, so there is no label-statistic leak. The EWMA is seeded from the first 20 non-spike returns and floored at 50 bp/day.

**Split-spike guard.** A daily close log-return with magnitude above `ln(1.5)` is treated as a likely split print. Such a return is excluded from the EWMA (both the recursive update and the seed window), and any label whose horizon spans one is masked out. The mask reads only the same future prices the label itself uses, so it adds no leakage.

## Model — `v5_backbone.py`

```
x (B, 252, 40)
 stem Linear(40 -> 256)  + zero-gated context/feed taps
 6 x V5Block: pre-norm [ Mamba | SwiGLU ], both AdaLN-Zero conditioned
 RMSNorm
 multi-scale read-out: concat[last day, mean last 21, mean last 126] -> Linear -> GELU
 4 horizon heads -> logits (B, 4, 60) -> softmax histogram
```

Mamba is the **only** temporal operator, so the network is causal end to end. There is no batch-dependent normalization anywhere. The loss is a masked histogram cross-entropy against HL-Gauss soft targets plus a small 3-class auxiliary term; masked entries are excluded with `torch.where` (never `loss * mask`, which `NaN * 0` would poison).

### Conditioning seams (present from v5.0, zero until grafted)

Three seams exist in the graph from the first run but contribute exactly zero until deliberately trained: **A** static per-ticker identity (AdaLN-Zero FiLM), **B** per-day cross-market context (zero-gated additive taps), **C** per-ticker external feed (insider/sentiment, zero-gated tap). Zero-initialized FiLM weights and zero-initialized tap gates make every seam's output the zero tensor, and the learned null inputs give them zero gradient during base training, so the pre-graft model is identical to a seam-free network. `optimizer_param_groups` keeps all seam parameters out of weight decay so that identity is not eroded. The seam-identity test asserts both the forward identity and the at-initialization invariant.

### Uncertainty

A deep ensemble of `M = 4` members (different seeds and shuffles). `Pred_Prob` is the ensemble-mean `P(up)`; `Pred_Prob_Std` is the std of `P(up)` across members (epistemic disagreement). `Score = P(up) - P(down)` is a signed conviction with its own member-wise std `Score_Std`. Per-horizon temperatures, fit on validation by minimizing the masked 3-class NLL of the ensemble mean, calibrate the marginals.

## Training — `run_train_v5.py`

```bash
# Production-scale (needs a GPU for tractable wall-clock):
python run_train_v5.py --eval-mode time --members 4

# Held-out-ticker generalization:
python run_train_v5.py --eval-mode ticker --ticker-holdout-frac 0.1

# End-to-end CPU verification (tiny model/universe/steps):
python run_train_v5.py --smoke --tickers AAPL MSFT IBM KO GE JNJ
```

- **Splits**: global chronological cutoffs (train 64% / val 16% / OOS 20%) on the window end date. At least one holdout axis (time or seeded ticker) must be active.
- **Embargo**: a window's labels may not use prices beyond its own split boundary; the per-horizon embargo dates are written for the backtest to audit.
- **Storage**: normalized rows in one concatenated fp16 memmap plus a per-ticker offset index; stride-1 windows are sliced on demand.
- **Optimizer**: AdamW (seam and 1-D params no-decay), 1k-step warm-up then cosine over a fixed step budget, grad-clip 1.0, step-anchored early stopping on validation CE.

Artifacts written: `models/v5/member_{0..M-1}.pt`, `models/v5/config.json`, `models/v5_meta.json`, `models/v5_norm.json`, `forecasts/split_info.json` (+ `oos_start_date.txt` in time modes), and one `forecasts/{TICKER}_forecast.csv` per evaluation ticker.

## Scoring and backtest

```bash
python run_live_signals_v5.py --tickers AAPL MSFT --min-accepted 0.2 --std-factor 0.0
python run_backtest_v4.py        # reads forecasts/, branches on eval_mode
```

The live scorer loads the v5 artifacts, builds the latest window per ticker through the same builder, runs the ensemble, and writes `signals/live_scores_{date}.csv` and `signals/live_decision_{date}.csv` with the `P(up)` semantics plus the bear/neutral, quantile, and `Score`/`Score_Std` columns; a ticker below the real-row floor is reported `insufficient_window` and tickers whose data lags the decision date are listed.

`run_backtest_v4.py` is unchanged on the time-holdout path: it reads the forecast CSVs with a `usecols` filter, so the added v5 columns are ignored and the existing strategy runs as before. Under `eval_mode=ticker` it runs over all dates of the held-out-ticker forecasts (there is no time cutoff).

## CPU fallback and tests

The fused CUDA Mamba kernel (`mamba-ssm`) is used when a GPU is present. On CPU-only hosts the model transparently uses `v5/mamba_ref.py`, a pure-PyTorch block with `mamba_ssm.Mamba` parameter parity (so GPU-trained checkpoints load unchanged) and a batched sequential scan.

```bash
python tests/run_tests.py        # no pytest dependency required
```

The suite covers: scan parity (the reference scan vs the fallback scan), checkpoint round-trip, the seam-identity invariant, NaN-safe masked loss, exact class marginals and bin-edge/threshold validation, the formula parity between the legacy preprocessor and the in-builder recompute, the split-spike label mask and EWMA exclusion, the embargo decision, the degenerate-scale fallback, the feature-name-hash guard, the fp16 round-trip, left-padded windowing, and the trained-artifact contracts above.

## Environment

PyTorch ≥ 2.4 is required. For GPU training, install `mamba-ssm==2.2.x` and `causal-conv1d>=1.2` against a CUDA 12 build of PyTorch; bf16 autocast needs compute capability ≥ 8.0. CPU-only hosts need none of the CUDA packages — the fallback covers construction, scoring, and the full test suite.
