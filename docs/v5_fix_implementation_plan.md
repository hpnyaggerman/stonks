## 0. Definitions and constants

- `z[t,h] = ln(C[t+1+d_h]/C[t+1]) / (σ̂[t]·√d_h)` — the label after P2.1 re-anchoring: volatility-normalized forward log-return over the earliest interval a signal computed from close(t) can actually hold (entry next close). `d_h ∈ {1, 5, 21, 126}` trading days; σ̂ is the causal EWMA vol (`features_v5.ewma_sigma_hat`), kept at the anchor t.
- `c[s,h]` — cross-sectional median of eligible `z` at (session s, horizon h); `z′ = z − c` is the trained target after P3.1 (market-relative return).
- `Score_h = P(up) − P(down)` — the consumer-aligned score; all gates, stopping, and consumers use it (raw `P(up)` is logged as the second score, never gated on).
- Rank-IC — per (session, horizon) Spearman correlation across tickers between a score and realized `z′`; computed only on dates with ≥ `IC_MIN_NAMES` mask-passing names.
- HAC t — mean(IC)/SE with Newey–West (Bartlett) standard error: `SE² = (Σ_b S_b)/N²`, `S_b = Σ e_t² + 2·Σ_{j=1..L} (1 − j/(L+1))·Σ_t e_t e_{t+j}` computed within each contiguous session block b (blocks combined as independent clusters), `e_t = IC_t − mean(IC)` pooled, adjacency by session index.

## Phase P1 — measurement first

### P1.1 Metrics module
Where: new `v5/metrics.py` (numpy/scipy only; no torch dependency in the math).
Change — public functions:
- `spearman_ic(scores, z, group_ids, min_names=30) -> (group_keys, ic_values)` — per-group Spearman, groups below the floor dropped; zero-variance score within a group → group dropped (never NaN).
- `hac_t(ic, session_idx, lag, block_ids) -> (mean, se, t, n)` — the HAC estimator of §0, within-block adjacency, blocks as independent clusters; on zero qualifying dates every suite function returns an explicit empty row (mean = se = t = NaN, n = 0) and never raises — the smoke gate-ledger invocation (gate floor 30 > the 6-ticker smoke universe) exercises exactly this path and must complete mechanically.
- `ic_suite(prob_up, prob_down, z, mask, meta, cfg, blocks=None, roles=None, tradable=None, alt_mask=None)` — per horizon and per score (`P(up)` and `Score`): per-date IC series, HAC t with `HAC_LAG`, mean, date count; optionally restricted by block role via per-label stored target dates, reported additionally on the tradability-filtered subset, and — when `alt_mask` is given — repeated on that alternative label mask (used for the uncensored-outcome sensitivity: `m_uncens` = isfinite ∧ has-future ∧ gap ∧ embargo with the spike term dropped, P3.5/D-1).
- `top_of_ranking(score, z, mask, meta, sigma=None, tradable=None, alt_mask=None)` — per date top-1 and top-decile mean realized `z′` with the same date floor and HAC treatment; the gate-facing variant is tradability-filtered (population = mask ∧ tradable — the diagnosis defines this metric as "mask-filtered, tradability-filtered", and cost claims are meaningless on the illiquid tail an unfiltered argmax selects), with the unfiltered variant reported beside it; `alt_mask` repeats it on the uncensored outcome set. It additionally reports the return-units variant — per date, the mean over the selected decile of `z′·σ̂[anchor]·√d` (the label's own denormalization: the market-relative log-return a decile trade would earn before costs), same floors and HAC treatment — because the 1d cost gate consumes THIS variant: a dimensionless z′ cannot be compared to a basis-point threshold (P6.3). σ̂ arrives via the `sigma` parameter, fed from P3.5's `sigma_hat` meta key (the memmap's `log_sigma_hat` channel cannot supply it — robust-z scaled and ±10-clipped, so numeric recovery fails exactly in the tails); the P1.2 scorer passes `f.sigma_hat[anchor]` from its rebuilt frames.
- `block_partition(val_sessions, n_blocks=4, phase=0) -> (bounds, roles)` — `np.array_split` of the sorted unique val sessions; roles alternate starting stopping.
- `stopping_score(t_1d, t_1w) = (t_1d + t_1w)/√2` — ordinal only (the two t's share dates and the 1d label path nests inside 1w, so the combination is not standard-normal; success gates never read it), with the degenerate guard: fewer than 10 usable stopping dates at either horizon → −inf.
- `uncertainty_quality(up_std, prob_up, z, mask, meta, cfg)` — per horizon: Spearman correlation of the ensemble-member std of P(up) with the realized absolute error |mean P(up) − 1{z′ > θ_h}| over mask-passing labels, plus a risk–coverage curve (mean absolute error by ascending-std decile); requires ≥ 2 members, so it runs in the P1.2 scorer and at finalize, never in per-member training evals (diagnosis S3(c) — the precondition for ever setting a nonzero `--std-factor`, P5.2).
- `null_shuffle_within_date(scores, meta, seed)` and `null_circular_shift(scores, meta, seed)` — evaluation-time nulls (a) and (b): within-date ticker permutation (destroys all cross-sectional signal, validates mechanics) and per-ticker circular shift of the date-sorted score series (destroys score–outcome alignment while preserving the IC series' serial correlation, which (a) cannot test).
Why: D3 — the run must measure what the product consumes (within-date ranking) at a cadence that can see it; every per-date metric filters by the stored per-label mask and target dates so 1m/6m predictions are never scored against outcomes inside the OOS year.
Tests (`tests/test_metrics.py`): planted-IC synthetic panel recovers sign and approximate magnitude; HAC SE exceeds naive SE on an AR(1) IC series; both nulls return |t| < 3 on planted-signal data (seeded); block partition covers all sessions disjointly; membership-by-target-date assigns no label to both roles; `uncertainty_quality` recovers a planted std–error correlation; the `alt_mask` population is a strict superset of the primary-mask population on a fixture with censored labels.

## Phase P2 — label pipeline (`features_v5.py`)

### P2.1 Re-anchor labels to next-close entry
Where: `features_v5._targets`.
Change: for horizon d — entry index `t+1`, target index `t+1+d`: `valid = t+1+d < n`; `y = logc[t+1+d] − logc[t+1]`; `denom = σ̂[t]·√d` (unchanged — causal at the anchor); `target_dates[t,h] = dates[t+1+d]`; spike window shifts to `(t+1, t+1+d]`: `spike_free = (cum_spike[t+d+2] − cum_spike[t+2]) == 0`. A split print at t+1 must NOT censor (both entry and target closes are on the post-split basis, so it cancels out of the ratio); a print at t+1+d must censor. Update the docstring formula.
Why: S5 execution timing — the old label covered (t, t+1], which live operation can never hold (fills happen no earlier than the next session's close); the old 1d head had zero overlap with the earliest honest holding interval. Re-anchoring aligns every horizon's label with an executable interval once, keeps 1d tradable, and barely moves 1w/1m/6m (interval overlap 4/5, 20/21, 125/126 was already high).
Propagation: `_embargo_dates` (P3.12), backtest entry timing (P5.1), the doc-level session-count formula 254−d → 253−d (no code change — block membership reads stored target dates).
Tests (`tests/test_features.py` extended): exact z on a synthetic geometric series; split at t+1 not censored; split at t+1+d censored; last valid anchor is `n − d − 2`.

### P2.2 Gap-aware and finite label mask
Where: `features_v5.label_mask`; new signature `label_mask(z, spike_free, target_dates, anchor_dates, split_end_dates, horizon_days=HORIZON_DAYS)`; caller `build_memmap_and_samples` passes `f.z`, `f.dates`.
Change: two new AND-criteria — `np.isfinite(z)` and `(target_dates − anchor_dates[:,None]) ≤ GAP_LIMIT_DAYS[h]` in calendar days. The additive +4 floor keeps every normal week; the measured span is anchor→target, which after P2.1 is d+1 sessions — a Friday-anchored 1d label targets Tuesday, 4 calendar days ≤ 6 — and the floor absorbs the extra session at every horizon (worst normal spans ≈ 4/10/32/185 calendar days vs limits {6, 12, 36, 193}).
Why: horizons are row-counted, so a "21-row" label across a halt or recycled symbol is not a 1-month return (48 usable tickers have > 730-day internal gaps); the isfinite term closes the channel where `v5_loss`'s `nan_to_num` would train a NaN label as a full-weight z = 0 target — previously empirically vacuous, load-bearing once P2.3's re-seed introduces NaN σ̂ mid-series.
Behavioral note: the gap criterion breaks mask monotonicity (a post-anchor halt can kill 1d while 6m survives), so with P3.2 thinning an occasional gap-straddling train anchor loses all labels and is skipped — intended; the build logs the count.
Tests: synthetic 30-day hole masks 1d/1w at the seam while a within-193-day 6m label survives; NaN-z rows masked.

### P2.3 EWMA re-seed after long gaps
Where: `features_v5.ewma_sigma_hat` → `(close, dates=None, reseed_gap_days=EWMA_RESEED_GAP_DAYS)`; module constant `EWMA_RESEED_GAP_DAYS = 90`; caller `build_feature_frame` passes dates.
Change: when the calendar gap from the previous row exceeds the threshold, reset the seed state (`seed_done = False`, `seed_vals = []`, σ̂ = NaN) so the next `EWMA_SEED_WINDOW = 20` non-spike returns re-seed the variance; the first post-gap return (which spans the halt) is excluded from the new seed; pre-re-seed rows carry NaN σ̂ and their labels die via P2.2's isfinite term.
Why **[decision]**: σ̂ currently freezes across a halt, so the first post-gap anchors normalize labels with pre-halt volatility; 90 days chosen because the census tiers gaps at > 90d (103 tickers) and below that the λ = 0.94 EWMA re-converges naturally with an ~11-session half-life.
Tests: synthetic 1-year gap → σ̂ NaN for 20 post-gap rows, then re-seeded near the post-gap regime's volatility.

### P2.4 FeatureFrame carries volume and tradability
Where: `features_v5.FeatureFrame`, `build_feature_frame`.
Change: new fields `volume` (raw), `tradable` (bool, causal: `close ≥ 5.0 ∧ rolling 63-session median(close·volume) ≥ 1e6`, `min_periods=63`, NaN → False), and `vol_med63` (float, causal 63-session rolling median of raw volume, `min_periods=63`, NaN where unavailable — the split detector's corroboration reference, transported by P4.3).
Why: the forecast `Volume`/`Tradable`/`VolMed63` columns (P4.3), S3 tradability stratification, and backtest cost realism all need them; computed once in the shared builder so trainer, live scorer, and backtest cannot drift.
Tests: threshold behavior on a synthetic frame.

### P2.5 Phantom-session filter at load
Where: `features_v5.load_us_ohlcv`; new `load_session_census()`; constant `PHANTOM_MIN_NAMES = 3`; census path `TrainingData/session_census.csv`.
Change: after the parquet read, drop rows whose date appears in the census with `n_names < 3`; dates absent from the census (newer than its end) pass unconditionally; missing census file → single warning, no filtering (small dev environments keep working). Any future feed append must regenerate the census in the same operation (P5.3 contract).
Why: 111 ≤ 2-name weekday phantom sessions (104 pre-1976 holidays, the 4 ancient singletons, the 3 OOS-tail holidays) plus 42 weekend rows occupy slots in `global_date_bounds`' fixed 254-session tails (three phantom holidays sit inside the current OOS tail), enter training as rows/labels/window content, and appear as 1–2-candidate "trading days" in the backtest calendar; a ≥ 3-name floor removes every phantom without touching the thin-but-genuine 1960s sessions (median genuine session had 9 names in 1962).
Tests: synthetic census + frames — listed phantom dates dropped, post-census dates survive.

### P2.6 Integrity counters at frame build
Where: `run_train_v5.build_frames`.
Change: log once per run, per era (half-open partition [data_start, 2008) / [2008, 2016) / [2016, data_end] **[decision]**): share of rows with σ̂ at `EWMA_SIGMA_FLOOR`, share with close < $1, and the per-horizon spike-censorship rate of labels; plus one line reporting `fear_greed.csv` coverage end vs the OHLCV data end (the frozen-fg span, S6).

## Phase P3 — trainer (`run_train_v5.py`, `v5_backbone.py`)

### P3.1 S1 — cross-sectional label centering
Where: new `center_labels(frames, bounds, eval_mode, eval_tickers, k_min)` in `run_train_v5.py`, called in `main` after `assign_eval_tickers` and the era audit, before `class_rate_log` and `build_memmap_and_samples` (its inputs — bounds and the holdout set — exist only there). Mutates `f.z` in place; returns stats for the log and `v5_meta.json`.
Change — definition: for every (session s, horizon h), pool = {`z[row,h]` over tickers | ticker ∉ `eval_tickers` under `eval_mode ∈ {ticker, both}`; row's date == s; row index ≥ `MIN_REAL_ROWS − 1` (enumerable anchors only — listing-era rows that can never train do not vote); label passes the full P2 mask with that row's `split_end` from `row_splits` (isfinite ∧ spike-free ∧ gap ∧ `target_dates ≤ split_end`)}. `c[s,h] = median(pool)` if `|pool| ≥ K` with `K = min(50, ceil(len(frames)/2))` (the scale-down keeps `--smoke`'s 6-ticker runs alive); apply `z[row,h] −= c[s,h]` to ALL frames including eval tickers; where c is undefined set `z[row,h] = NaN` (masked via isfinite — a mixed centered/uncentered target would be incoherent).
Implementation: per horizon, one concatenated pass — `date_idx = searchsorted(bounds["unique_dates"], f.dates)` per frame; collect (date_idx, z) over eligible labels into flat arrays; sort by date_idx; segment medians via `np.split` at boundaries → `c_table (n_sessions, 4)` float32, NaN where pool < K; second pass subtracts by lookup. ~26M×4 values; minutes of runtime, < 1 GB working memory.

A down print (ln r < 0) is a forward split iff ∃ρ with |ln r + ln ρ| ≤ 0.02 and volume ≥ (ρ/2)·`VolMed63`; an up print (ln r > 0) is a reverse split iff ∃ρ with |ln r − ln ρ| ≤ 0.02 and volume ≤ (2/ρ)·`VolMed63`; zero/absent volume or NaN `VolMed63` skips the corroboration test (snap-only detection, counted separately). Detected → back-adjust all prior closes by the exact ratio and log it **[decision: adjust, not exclude — keeps the ticker and its genuine history in P&L]**. Returns spanning > 7 calendar days are never split candidates (a multi-week gap move is a legitimate multi-session return, which v4 falsely whole-ticker-rejected). Non-snapping large prints stay in P&L — the majority are genuine moves; a blanket exclusion would delete real crashes and create an upward bias a deployed strategy cannot replicate. No whole-ticker rejection, no full-series pre-scan conditioning the daily candidate set on future prints (v4's directional look-ahead: reverse splits follow collapses, so future losers were preferentially deleted). Causality rule, explicit: candidate selection, the tradability gate, and the detector's corroboration statistic at date t read ONLY as-printed values dated ≤ t (the transported `Tradable`/`VolMed63` columns are as-printed and causal by construction; volume is never adjusted); back-adjusted closes exist only inside return booking and equity marks, where a ratio detected at session s may enter only quantities evaluated at sessions ≥ s — a mid-hold split adjusts the trade's return at exit, it never re-ranks any earlier day's candidates (a single back-adjusted series feeding the $5 floor would promote future reverse-splitters ×ρ at dates before the split — exactly v4's directional look-ahead reborn).
- Candidates: at each union-calendar date t with no open position: {(ticker, h) | h not excluded, `Score_h` > floor_h, `Tradable` == 1 at t (the transported P2.4 flag)}. Pick argmax `Score_h`. A position's exit date admits no new candidate — re-entry earliest the following union date (the exit-day re-entry blackout that the null protocol below and the ≤ ~84 round-trips/yr cost arithmetic in §6 both assume).
- Execution: entry at the ticker's NEXT own-session close after t (t+1 fill, matching P2.1's re-anchored labels; no next print within 5 calendar days **[decision]** → skip, counted); exit target = entry + d_h ticker-sessions; realized return = entry close → exit-date close on the ticker's own calendar; ticker dies before the scheduled exit → forced exit at the last print with the loss booked and `forced_exits` incremented, the haircut applied when the last print precedes the global OOS end by > 5 sessions **[decision]** (delisting proxy — the feed carries no delisting-reason field; the parameter makes the bankruptcy-vs-acquisition sensitivity explicit instead of silently booking last-print recovery); a horizon crossing the OOS end exits clamped at the final session, booked and flagged (never NaN). Equity path = daily mark-to-market of the held ticker's own prints; the trade log and equity path are one accounting (v4 booked `Actual_LogR` on the ticker calendar while exiting on the union calendar and dropped mid-hold deaths from the success count).
- Costs: exit equity multiplied by `(1 − cost_bps·1e-4)`; the full report repeats at each grid point.
- Null: `--null-runs` seeded replays picking uniformly from each day's gated candidate set under the identical protocol (same floors, exclusions, tradability, t+1 fill, horizon hold, exit-day re-entry blackout, forced exits included); report the strategy's percentile and z against the null distributions of total return, CAGR, max drawdown (v4's null was always-invested daily 1d picks that never experienced the delisting path, 50 runs, and a no-op `*5` list replication).
- Benchmark **[decision]**: default SPY source = `TrainingData/indicators_data/processed/SPY-VIX/SPY_daily_processed.csv` (the v4 artifact, ends 2026-04-23 — SPY has zero rows in the parquet shards, measured, so no fresher in-repo source exists; the P5.3 refresh contract covers it); SPY closes forward-filled only within their real span — the comparison truncates at min(OOS end, last real SPY date) rather than flat-filling (v4 flat-filled the final ~32 sessions); price-only SPY printed with the explicit ~1–1.5%/yr dividend-omission caveat; `--spy-tr-csv` preferred when supplied — the diagnosis's "use total-return SPY" is thereby optional-input, not default, because no TR series exists in the repo and fabricating one is worse than a labeled caveat.
- Output: `videos/backtest_metrics_v5.json`, `trade_summary_v5.csv` (adds EntryDate/ExitDate, EntryClose/ExitClose, CostBps, ForcedExit, HaircutApplied, SurfaceTag), one equity PNG; header states: descriptive only — §6's IC/CE gates adjudicate, a single 254-session single-position path cannot.
Tests (`tests/test_backtest_v5.py`): synthetic forecast fixture — 2:1 forward split detected and back-adjusted (v4 booked a fake ~−69% loss); reverse split does not delete the ticker; a genuine −50% crash on flat volume (snap-shaped, corroboration-failing) is NOT adjusted; mid-hold delisting books the loss and counts a forced exit; entry is t+1 (≠ signal close); cost-grid arithmetic; null runs respect the gates and blackout.

### P6.3 Decision gates (contract, restating diagnosis §6 with entailed conjuncts made explicit)
Evaluated once per run at the early-stop-selected checkpoint (members as supporting evidence, the finalize ensemble as the gating object); success gates read gating blocks only; a failure reading may use full years (winner's curse inflates stopping-half statistics, so the full-year lens is conservative for failure); any qualifying result must persist at the stopping-block metric across the evals neighboring the selected checkpoint (from the eval history; zero extra gating looks) — operationalized **[decision]** as: at each of the evals at offsets −2, −1, +1, +2 from the selected eval (clipped at history ends), the stopping-block combined score keeps the selected eval's sign and at least half its value; frozen into P6.1.
- Horizon scope: 1w and 1m carry the standard gates; 1d is gated only cost-conditioned — the tradability-filtered top-decile must clear the cost model, operationalized **[decision]** as: pass iff the HAC t of the per-date series (return-units top-decile mean at 1d − 25 bp) is ≥ 3, with the 10 bp variant reported beside (the diagnosis's "clear the S5 cost model at 10–25 bp" names neither the z′→return conversion nor the significance arithmetic; this pins the conservative grid point with the same 3σ discipline as the other gates, on P1.1's return-units variant — a dimensionless z′ cannot be compared to a bp threshold) (the unfiltered figure is reported but never gates; cost claims are meaningless on the illiquid tail; most-powered horizon, but ≤ ~84 round-trips/yr under the v5 protocol — candidate t → entry t+1 → exit t+2 → blackout is a 3-session cycle; the diagnosis's ~126 assumed v4's same-close 2-session fill — ≈ 8–17%/yr at 10–20 bp, ≈ 21%/yr at 25 bp); a cost-cleared 1d gate counts toward success; 6m is report-only everywhere; 1m is adjudicated pooled-only on its ~2 gating blocks per year.
- Strong single-year success: gating-block t ≥ 3 at 1w on the primary run → continue immediately; rolling-origin runs proceed in parallel as confirmation before any deployment-scale conclusion.
- Pooled success: overlap-corrected |t| ≥ 3 at 1w (pooled gating halves over 3–4 years) or 1m (pooled gating blocks), with a year-clustered SE reported beside the pooled HAC t and the per-year floor: no per-year mean IC below −1 per-year SE (a pooled 3σ carried by one anomalous year does not qualify) → continue.
- Exploitability rider: any "exploitable" verdict additionally requires the tradability-filtered ICs to hold at the pre-registered threshold and the tradability-filtered top-of-ranking metric to confirm.
- Failure (an exclusion bound, not a nonexistence claim): full-year pooled |t| < 1.5 at both 1w and 1m, no cost-cleared 1d success, and centered val CE never beating the centered baseline in any year → "no signal of exploitable size demonstrated" — the verdict covers cost-adjusted 1d alongside 1w/1m (rules out IC ≳ 0.03–0.05 at ~2σ; does not exclude IC ≈ 0.02); the discussion moves to features/horizons, and the comparator ICs separate feature-set-dead from pipeline-dead.
- Residual band: pooled t ∈ [1.5, 3) → failure path decision-wise, documented separately (licenses cheap follow-ups a clean failure would not: feature ablations, horizon changes).
- CE is secondary everywhere: any CE claim is judged as a paired per-date (model − baseline) difference with a HAC/bootstrap SE at the selected checkpoint, never as a raw scan of point values.
